# 운영 AI 검수와 제한 Beta

2026-11-01 기준 **운영 검수 준비 문서**입니다. 사용자 결정에 따라 호스팅·도메인과 실제 배포 검수는 현재 작업 범위에서 제외합니다. 로컬 검수는 계속 진행하며, 결과는 [로컬 AI 검수 기록](../LOCAL_AI_QA.md)에 별도로 기록합니다. 로컬 통과를 실제 배포 완료로 처리하지 않습니다.

## 시작 전 확정할 내용

| 항목 | 현재 상태 | 다음 행동 |
|---|---|---|
| 호스팅·OS·도메인 | 현재 범위에서 제외 | 추후 배포를 재개할 때 SINGLE_SERVER.md 확인. 로컬 작업의 선행 조건이 아님 |
| 결과물 이용 | 수정·재배포·상업적 이용 허용 | 사용자 자료와 외부 라이선스 준수 안내 유지 |
| 개인정보·나머지 약관 | 검토본 | POLICY_RELEASE.md의 담당 절차·계약·보관·시행일 확정 |
| Beta 대상·기간·예산 | 미정 | 참여 범위, 운영 담당자, 허용 비용과 중단 기준 결정 |

정책·접근 범위가 준비되기 전에는 외부 참여자를 모집하지 않습니다. 키·환경 파일·원본 사용자 자료를 검수 기록에 넣지 않습니다.

## 검수 순서와 통과 기준

각 행은 실행 후 날짜·릴리스 커밋·실행자·결과·증거 위치를 기록합니다. 미실행은 통과가 아닙니다.

| 순서 | 검수 | 통과 기준 | 현재 |
|---|---|---|---|
| 1 | 서비스 계정으로 check:deploy | 모든 항목 PASS, 실제 방화벽·TLS·Nginx 별도 확인 | 미실행 |
| 2 | HTTPS 홈·health·사용량·쿠키 | 페이지/API 정상, Secure·HttpOnly·SameSite 확인, 외부 3001 차단 | 미실행 |
| 3 | 샘플 CMS·저장·재진입·ZIP | 저장 복원과 ZIP 직접 실행 성공, 기존 작업 보존 | 미실행 |
| 4 | 실제 AI 생성 4개 유형 | 분석·관리자·프로젝트·모니터링 각각 유효한 결과, 요청한 구성·한국어·차트 표시 확인 | 미실행 |
| 5 | 선택 컴포넌트 및 전체 AI 수정 | 요청 반영, 비대상 데이터 보존, Undo 복원 | 미실행 |
| 6 | 취소·실패·사용량 | 기존 작업 보존, 실패 차감 제외·예약 반환·한도 메시지 확인 | 미실행 |
| 7 | 재시작·백업 복원·롤백 | 영속 한도 유지, 격리 복원 검증, 이전 릴리스 정상 구동 | 미실행 |
| 8 | 제한 Beta | 합의한 대상·기간·예산 내 운영, 오류·지연·토큰 기록 검토 | 미실행 |

4~5는 샘플 자료만 사용하며 실제 호출 비용이 발생합니다. 우선 한 유형의 생성·수정을 확인하고 실패하면 원인을 해결한 뒤 확대합니다. 비용 한도까지 반복 호출해 오류를 재현하지 않습니다. 취소나 실패에도 공급자 비용은 발생할 수 있습니다.

기존 `test:live`는 공급자를 직접 호출하는 4개 생성+1개 수정 검사이고, `test:live:edit`는 2개 수정 검사입니다. 각 작업은 복구 호출을 최대 1회 추가할 수 있습니다. 이 명령들은 HTTPS·프록시·쿠키·사용량 API 검수를 대체하지 않으므로 운영 검수는 실제 UI 흐름도 확인합니다. 이번 준비 작업에서는 실행하지 않았습니다.

## 진단 기록 집계

저장소 루트에서 실행합니다. 기본 기간은 최근 24시간이며 1~720시간만 허용합니다.

```powershell
npm.cmd --prefix backend run report:ai
npm.cmd --prefix backend run report:ai -- 168
```

Linux 운영 환경은 릴리스의 backend 디렉터리에서 서비스 계정으로 실행합니다.

```sh
node --env-file=/etc/sebit/backend.env --import tsx src/reportTelemetry.ts 24
```

기존 `AI_TELEMETRY_DB`를 읽기 전용으로 열고 JSON 집계를 출력합니다. DB가 없거나 형식·권한·기간이 잘못되면 종료 코드 1로 실패하며 DB를 만들지 않습니다. AI 호출이나 기록 삭제는 하지 않습니다. 공개 API를 추가하지 않았습니다.

- `from` / `to`: UTC 집계 구간. 완료 기록 시각 기준이며 진행 중 요청은 포함하지 않습니다.
- `requests`: 종류별 기록된 최종 요청 수, 성공·실패, 평균/최대 응답 시간(ms), 복구 호출이 있었던 요청 수. 성공 비율은 succeeded / completed로 계산하며 0건이면 판단을 보류합니다.
- `providers`: 복구를 포함한 공급자 시도 수와 **알려진** 토큰 합계. 최종 요청 기록의 토큰은 다시 합산하지 않습니다. `attemptsWithKnownTotal`이 attempts보다 작으면 총 토큰 정보가 일부 누락된 상태입니다. 모두 미상이면 합계는 null입니다.
- `failures`: 최종 실패의 종류·코드별 건수. 요청 ID·입출력 원문·키·모델명·DB 경로는 출력하지 않습니다.

집계는 기록된 이벤트 기준입니다. 프로세스 강제 종료, 기록 실패, 일부 사전 거절, 보관 기한 경과로 실제 요청 전체와 다를 수 있습니다. 구간 경계의 공급자 호출과 최종 요청도 서로 다른 구간에 들어갈 수 있습니다. 과금액·청구서·고유 사용자 수·실시간 동시성 또는 UI 체감 지연을 나타내지 않습니다. 비용은 운영 계정의 실제 청구 기록과 별도로 대조합니다.

## 중단과 결과 기록

데이터 손실·비밀 노출·한도 우회·예산 초과 또는 반복 생성 실패가 확인되면 신규 참여 확대를 중단합니다. 필요하면 배포 가이드의 점검 모드로 AI를 차단하고 기존 샘플/CMS/다운로드를 확인합니다. 운영 DB를 삭제해 오류를 해결하거나 한도를 초기화하지 않습니다.

검수 기록 양식:

```text
일시 / 실행자 / 릴리스 커밋:
환경 / 브라우저 / 유형:
시나리오 / 기대 결과 / 실제 결과:
성공·실패 / 응답 시간 / 알려진 토큰 / 누락 여부:
증거 위치(민감 정보 제외):
발견 문제 / 조치 / 재검수 결과:
공개 진행 또는 보류 / 결정 근거:
```

전체 공개 조건은 정책 확정, 실제 배포 검증, 운영 AI·Beta 검수입니다. 현재는 호스팅·도메인과 실제 배포를 제외하고 로컬 기능·AI 검수를 진행합니다. 로컬 검수 후에는 사용자 수동 사용성 확인과 정책 미확정 정보 정리를 이어갈 수 있으며, 배포 환경 결정을 매번 선행 조건으로 요구하지 않습니다.
