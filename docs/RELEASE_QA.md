# Chrome/Edge 통합 QA 및 배포 준비 점검

검수 기준: 2026-10-31, `main`의 `39648b5`에서 `검수/브라우저-통합QA` 생성.
이 문서는 로컬 검수와 실제 배포 검증을 구분한다. 외부 공개 배포는 수행하지 않았다.

## 환경과 재현

- Windows, Node.js 24.16.0.
- 설치된 Google Chrome 156.0.8078.48 / Microsoft Edge 156.0.4314.50의 headless 모드. Playwright의 격리 프로필을 사용하며 사용자 브라우저 데이터는 수정하지 않는다.
- 프론트엔드 위치: `sebitcanvers_v3/frontend`. 두 브라우저가 설치돼 있어야 한다.

```powershell
cd sebitcanvers_v3/frontend
npm.cmd run test:qa
npm.cmd run test:qa:preview
```

`test:qa`는 Vite 개발 서버 5174에서 기존 40개 시나리오를 Chrome·Edge 각각 실행한다. `test:qa:preview`는 먼저 프로덕션 빌드하고 별도의 Vite Preview 서버 5175에서 16개 조합을 두 브라우저로 확인한다. Preview 서버는 실제 Nginx/TLS 환경을 대체하지 않는다. 5175 포트는 다른 프로세스가 사용하지 않아야 한다.

API 응답은 기존 테스트의 모의 응답을 사용하고, 빌드 조합 검사에서는 `/api/**`를 테스트 응답으로 차단한다. 이번 검수는 실제 유료 AI 호출의 품질·지연·운영 계정을 검증하지 않는다.

## 검수 범위와 결과

**기존 시나리오 80개(40×2)와 빌드 조합 32개(16×2), 총 112개 통과.** 기능 코드 수정이 필요한 실패는 발견되지 않았다. Chrome CMS와 Edge의 1366px Dark Preview 스크린샷도 직접 확인했다. 모든 화면의 시각·접근성 전수 검수를 뜻하지는 않는다.

| 범위 | 확인 내용 | 결과 |
|---|---|---|
| 기존 브라우저 흐름 | 생성·AI 수정의 성공/실패/취소·시간 초과·늦은 응답, CMS·Undo·Finalize·ZIP 직접 실행, 재생성·복원·삭제·이미지 정리·탭 잠금·사용량·안내 페이지 | 통과 |
| 빌드 결과 조합 | 분석/관리자/프로젝트/모니터링 × Modern/Minimal/Corporate/Dark, 각 조합의 샘플 Preview·확정·ZIP JSON·라이선스 파일 | 통과 |
| PC 폭 | 1280·1366·1440·1920px을 16개 조합에 순환 배정. 모든 조합×모든 폭(64개)의 전수 검사는 아님 | 통과 |
| 프론트엔드 | 단위 57개, 프로덕션 빌드, 린트 | 통과 |
| 백엔드 | 타입 검사, 테스트 22개 | 통과 |

실패 시 screenshot·trace, 성공한 주요 흐름과 빌드 Preview의 screenshot, HTML 보고서는 `test-results/`, `playwright-report/`에 생성한다. 빌드 검사 결과는 하위 `preview/`에 저장한다. 자동 생성 자료는 Git에 올리지 않으며 다음 검사 때 교체될 수 있다.

Windows 제한 실행 환경에서는 Preview 자식 프로세스 종료가 대기하는 현상이 있었다. 검사가 모두 통과한 것을 확인한 후 이번 검수 전용 프로세스만 정리했다. Preview 실행 명령은 npm 래퍼를 줄여 Vite의 Node 진입점을 직접 실행하도록 구성했다. 프로세스 종료 권한이 있는 실행 환경에서 Chrome·Edge 대표 2개를 다시 실행해 **정상 자동 종료와 exit 0**을 확인했다. 서버 종료 권한이 제한된 에이전트 환경에서는 같은 현상을 앱 실패로 오인하지 말고 테스트 결과와 프로세스 상태를 구분한다.

## 배포 설정 점검

| 항목 | 로컬에서 확인한 내용 | 실제 서버에서 남은 검증 |
|---|---|---|
| 실행 버전·공유 코드 | Node 24.16.0, 프론트 빌드·백엔드 타입/테스트 통과. 백엔드가 프론트 공유 Schema를 참조 | 전체 저장소 릴리스 경로와 서비스 계정, 자동 재시작 |
| 운영 시작 조건 | production의 HTTPS origin·루프백 host·신뢰 로컬 프록시·서로 다른 절대 DB 경로 검사 및 관련 테스트 통과 | 실제 도메인·환경 파일·서비스 관리자 적용 |
| 프록시/IP 한도 | 신뢰한 peer만 단일 X-Forwarded-For 사용, 위조 체인 거부·한도 분리·Secure 쿠키 테스트 통과 | Nginx의 헤더 덮어쓰기·외부 3001 차단·HTTPS 왕복 |
| 정적 배포물 | 빌드 dist 파일 목록에 환경 파일·DB 없음. Git 추적 목록에 `.env`·SQLite 파일 없음 | 웹 루트가 dist인지, 비밀 경로 접근 차단·권한·백업 경로 |
| AI 연결 | 모의 공급자를 통한 오류·한도·타임아웃·통계 기록 검사 | 운영 계정의 실제 생성/수정 호출, 비용·로그 확인 |
| Nginx | 단일 서버 예시에 HTTPS·dist 루트·루프백 API·재시도 없음·130초 대기 명시 | 실제 Linux의 `nginx -t`, 인증서 발급/갱신, reload |
| 영속 데이터·복원 | 코드의 경로 검증 및 SQLite 재열기·한도 테스트 | DB/저널 백업·복원, 재부팅·롤백, 디스크/로그 보관 |
| 정책 | 회사 연락처 반영, 검토본 표시 유지 | 개인정보 담당 절차·상업 이용·국외 처리·보관·시행일 확정 |

실행 절차는 [단일 서버 운영 가이드](deployment/SINGLE_SERVER.md), 정책 확인 항목은 [정책 공개 준비](POLICY_RELEASE.md)를 따른다. 이 표의 코드·테스트 통과를 실제 방화벽·인증서·정기 파기·보호된 백업까지 적용된 것으로 해석하지 않는다.

## 공개 전 남은 단계

1. **정책 확정:** 담당 절차·이용 조건·실제 제공업체 계약과 보관 설정을 확인해 검토본을 확정본으로 변경.
2. **실제 배포 환경 검증:** 호스팅·도메인·TLS·서비스 계정·영속 DB·로그·백업/복원·롤백 적용 및 확인.
3. **운영 환경 최종 검수와 제한 Beta:** HTTPS에서 실제 AI 생성/수정, 사용량·실패 복구·ZIP 및 운영 모니터링 확인.

위 항목이 끝나기 전에는 공개 V1 전체 완료로 표시하지 않는다. 이번 로컬 QA와 별도로 새로운 기능 묶음을 추가한 것은 아니다.
