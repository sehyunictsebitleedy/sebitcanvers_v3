# SEbit Canvers V3

**AI가 초안을 만들고, 사용자가 직접 완성하는 PC Dashboard Builder.**

사용자가 제작 조건을 선택하면 AI가 샘플 데이터 기반 대시보드를 생성하고,
AI 수정과 CMS Editor로 다듬은 결과를 HTML/CSS/JavaScript 소스 ZIP으로 제공합니다.
회원가입·로그인 없이 무료로 사용하는 PC 전용 제작 도구를 목표로 합니다.
실제 업무 데이터에 연결된 시스템이나 완성 템플릿 선택 서비스와는 구분합니다.

이 문서는 [AI Dashboard Builder V1 최종 기획서](AI_DASHBOARD_BUILDER_V1_PLAN.md)
v1.0(2026-09-30)의 요약입니다. 아래 기획 범위는 구현 완료를 의미하지 않으며,
현재 구현 상태는 별도로 명시합니다. 기획서 원문의 정식 서비스명은 미정입니다.

- 검증 결과: 프론트엔드 33개·백엔드 9개 테스트 및 상태 배지 브라우저 시나리오 1개 통과(긴 문구, 숨김·삭제·복원·확정). 밝은/어두운 배경을 확인했고 빌드·린트·백엔드 타입 검사도 통과했습니다. 실제 유료 AI 호출은 수행하지 않았습니다.
- 다음 작업은 **메뉴 순서·표시/숨김·아이콘 편집**입니다. 공개 V1의 6개 작업 묶음 중 1단계를 진행 중이며, 1단계 전체 완료는 아닙니다.

- 실제 생성 장애 확인: 프론트엔드만 실행되고 백엔드가 꺼져 있었습니다. 백엔드 실행 및 외부 API 접근 확인 후 프론트엔드 프록시를 통한 생성이 HTTP 200으로 완료됐고, 컴포넌트 7개의 Schema 검증도 통과했습니다. 관측된 성공 요청은 약 28~34초가 소요됐습니다.
- 추가한 Summary/Activity/Button의 AI Patch는 자동 테스트로 검증했습니다. 새 컴포넌트 각각의 실제 모델 수정 품질은 후속 검수 대상입니다.
- 다음 시작점: 최신 브랜치에서 새 한글 브랜치를 만들고 **Status Badge**부터 진행합니다. 남은 공개 V1 작업은 아래 6개 묶음을 기준으로 관리합니다.

개발 재시작은 PowerShell 터미널 두 개에서 각각 실행합니다. 저장소 최상위 폴더 기준이며, PowerShell의 `npm.ps1` 실행 제한이 있는 환경에서는 `npm.cmd`를 사용합니다.

```powershell
# 프론트엔드 터미널
cd .\sebitcanvers_v3\frontend
npm.cmd run dev
```

```powershell
# 별도 백엔드 터미널
cd .\backend
npm.cmd run dev
```

프론트엔드는 터미널에 표시된 Local 주소로 접속합니다. AI 기능은 백엔드도 실행돼 있어야 하며, 백엔드·공유 Schema 변경 후에는 백엔드를 재시작합니다. API 키는 로컬 `backend/.env`에서만 관리하고 커밋하지 않습니다.

### 이전 작업 — Button 컴포넌트 (2026-10-20)

- 브랜치: `기능/버튼-컴포넌트`.
- 편집기에서 **버튼 추가** 후 문구·주소·Primary/Secondary/Ghost/Danger 스타일과 Small/Medium/Large 크기를 변경합니다. Danger는 시각적 스타일이며 삭제 동작을 수행하지 않습니다.
- 동작 범위는 링크 이동입니다. http/https 주소는 새 창으로 열고, `#dashboard-data`는 데이터 영역으로 이동합니다. 임의 스크립트·프로토콜과 존재하지 않는 내부 주소는 저장할 수 없습니다.
- 편집 중에는 선택만 가능하며 미리보기와 ZIP에서 링크가 작동합니다. 내부 이동 시 앱의 프로젝트 주소를 유지합니다.
- 실행 취소·저장·복원·AI Patch·ZIP 출력에 연결했습니다. 버튼만 남기고 마지막 데이터 컴포넌트를 삭제하거나 숨기는 변경은 차단합니다.
- 검증: 프론트엔드 테스트 31개, 백엔드 테스트 9개, 버튼 브라우저 시나리오, 빌드·린트·백엔드 타입 검사. 실제 유료 AI 호출은 반복하지 않았습니다.

### 남은 작업 — 공개 V1까지 6개 작업 묶음

기획서의 원래 Phase 번호가 아니라, 현재 코드와 미완료 요구사항을 기준으로 묶은 실행 순서입니다. 한 묶음에 여러 작업이 포함되며 **6번의 작업 요청으로 끝난다는 의미는 아닙니다.** CRM은 계속 제외합니다.

| 순서 | 작업 묶음 | 남은 내용 및 완료 기준 |
|---|---|---|
| 1 | Library·CMS 세부 기능 보완 (진행 중) | 독립 Status Badge 구현 완료. 메뉴 아이콘·순서·표시/숨김, Header 날짜 옵션 등 남은 속성을 대조하고 편집·Export까지 연결 |
| 2 | 프로젝트 관리·저장 복구 완성 | 최초 생성 Snapshot으로 초기화, 프로젝트 삭제 확인, 보관·이미지 정리 정책, 저장 버전·손상/차단/용량 초과 복구 기준 확정 및 검증 |
| 3 | AI 대기 UX·품질 검수 | 생성 소요 시간 안내와 취소·재시도 개선, 연결 실패/취소/시간 초과 구분, 새 컴포넌트 포함 실제 AI 수정·데이터 보존 검수. 생성 30~60초는 기획 목표이며 보장 시간이 아님 |
| 4 | 공개 운영·비용 제한 | 생성/수정별 사용 한도, 실패 차감 정책, 재시작·다중 서버에서도 유지되는 제한 저장소, 토큰·비용·오류 관측과 운영 접근 보호 |
| 5 | 이용 안내·정책 확정 | 실제 운영 방식에 맞춘 이용약관·개인정보·로컬 저장·AI 결과 이용 안내와 라이선스 표시, Footer 연결. 정책과 보관 기간은 서비스 운영자가 최종 확정 |
| 6 | 통합 QA·배포 | 4개 유형과 스타일·이미지·신규 컴포넌트 조합, Chrome/Edge·해상도·접근성, 압축 해제한 ZIP의 직접 실행·Preview 일치, 배포 설정·모니터링·롤백 및 제한된 Beta 검증 |

1~3은 제작 기능 완성, 4~6은 무료 공개 서비스 출시 준비에 해당합니다. 전체 필수 완료 기준을 통과하기 전에는 V1 전체 완료로 표시하지 않습니다.

- 공통 렌더러 CSS를 사용하므로 홈 예시, 생성·편집 미리보기, 새로 내려받는 ZIP에 동일하게 반영됩니다.

### 이전 작업 — 활동 목록 추가 (2026-10-20)

- 브랜치: `기능/활동목록-추가`. Activity 한 종류를 추가했습니다.
- 편집 화면 왼쪽 **활동 목록 추가**로 시작합니다. 각 항목의 제목·설명·표시 시간·아이콘을 편집하고 추가·삭제·위로 이동할 수 있습니다.
- 목록은 최대 20개이며, 제목 120자·설명 500자·표시 시간 80자까지 입력합니다. 시간은 샘플 표시 문구이며 자동 시간순 정렬은 하지 않습니다. 아이콘은 안내·완료·대기·주의 중 선택합니다.
- 빈 목록 안내, 실행 취소, 너비·표시 여부, 저장·새로고침 복원, 최종 검증·ZIP 출력에 연결했습니다. AI Patch에서도 목록 전체 교체를 지원합니다.
- 검증: 프론트엔드 테스트 29개, 백엔드 테스트 9개, Activity 및 Summary 브라우저 검사, 빌드·린트·백엔드 타입 검사. 이번 작업에서 실제 유료 AI 호출은 수행하지 않았습니다.
- Create 기본 선택 항목과 4개 유형은 유지합니다. 다음 후보는 Button 컴포넌트이며, 공개 배포용 사용량·비용 제한은 별도 작업입니다.

### 이전 작업 — 요약 카드 추가 (2026-10-20)

- 브랜치: `기능/요약카드-추가`. 이번 범위는 추가 V1 컴포넌트 중 Summary 한 종류입니다.
- 편집 화면 왼쪽 **요약 카드 추가**로 제목·표시 값·설명을 담은 카드를 추가합니다. 표시 중이며 공간이 있는 첫 섹션에 배치합니다.
- 제목 120자, 표시 값 80자, 설명 500자까지 지원합니다. 너비·표시 여부·순서 변경·삭제·실행 취소와 저장·새로고침 복원·ZIP 출력에 연결했습니다.
- AI Patch에 요약 카드 추가와 설명·표시 값 수정 계약을 연결했습니다. 이번 작업에서는 실제 유료 API 호출 없이 자동 테스트로 검증합니다.
- Create 기본 선택 항목과 CRM을 제외한 4개 유형은 유지합니다. 요약 카드는 생성 후 편집기에서 추가할 수 있습니다.
- 검증: 프론트엔드 테스트 27개, 백엔드 테스트 9개, 요약 카드 브라우저 시나리오, 프론트엔드 빌드·린트와 백엔드 타입 검사.
- 다음 후보: Activity 목록 컴포넌트. Button과 공개 배포용 사용량·비용 제한은 별도 작업으로 남겨둡니다.

### 이전 작업 — 새로고침 시 프로젝트 자동 복원

- 브랜치: `기능/프로젝트-자동복원`.
- 작업 주소를 `#workspace/프로젝트ID`로 저장하여 새로고침 시 해당 프로젝트의 마지막 저장 내용을 복원합니다. 뒤로/앞으로 가기로 프로젝트를 전환해도 해당 작업을 불러옵니다.
- 확정·다운로드 완료 상태는 미리보기로 복원하며, 편집을 시작할 때만 편집 중 상태로 변경합니다. 새로고침 후 ZIP 다운로드는 다시 검증·생성합니다.
- 삭제되거나 손상된 프로젝트, 잘못된 주소는 홈에서 안내하며 기존 저장 데이터를 덮어쓰지 않습니다. 이전의 ID 없는 `#workspace` 주소는 최근 작업에서 다시 선택해야 합니다.
- 복원 범위는 같은 브라우저·같은 사이트 주소의 저장된 디자인입니다. 저장하지 못한 변경, 진행 중 AI 요청, 선택 중인 편집 항목은 복원하지 않습니다.
- 검증: 편집 내용 새로고침 복원, 여러 프로젝트 및 브라우저 이력 이동, 홈 유지, 누락·손상 데이터 보존, 확정 상태 복원 브라우저 테스트 3개와 빌드·린트.
- 이번 작업은 자동 복원까지만 진행합니다. 후속 후보는 추가 V1 컴포넌트와 공개 배포용 사용량·비용 제한입니다.

### 이전 작업 — 재생성과 이전 디자인 복원

- 작업 브랜치: `feat/regeneration-backup` (도넛 차트 넘침 수정 포함).
- 편집 화면 상태줄의 **재생성**에서 기존 선택 조건을 유지하거나 변경할 수 있습니다. CRM은 제외한 4개 유형을 제공합니다.
- 교체 확인 후 정상 생성·백업·저장이 완료됐을 때만 새 디자인을 반영합니다. 취소, AI 실패, 저장 실패 시 기존 디자인을 유지합니다.
- 프로젝트 ID와 최초 생성일은 유지하며, 교체 직전 디자인 1개를 브라우저에 백업합니다. 프로젝트를 다시 열어도 **이전 디자인 복원**을 사용할 수 있습니다.
- 복원 시 현재 디자인을 백업으로 교체하며, ZIP 다운로드는 다시 확정해야 합니다. 브라우저 데이터를 삭제하면 백업도 삭제됩니다.
- 실제 API 검수: 분석·관리자·프로젝트·모니터링 생성 각 1건과 AI 제목 수정 1건 모두 통과(Repair 없음). 이는 전체 품질이나 모든 요청의 성공을 보장하는 검수는 아닙니다.
- 검증: 프론트엔드 단위 테스트 25개와 Chromium 테스트 9개 통과(재생성·취소·실패 보존·재진입 복원 포함), 빌드와 린트 통과.
- 이후 작업: 작업 화면 새로고침 시 열린 프로젝트 자동 복원은 위 최신 작업에서 완료했습니다. 추가 V1 컴포넌트, 공개 배포용 사용량·비용 제한은 남아 있습니다.

아래 날짜별 기록의 ‘실제 AI 검수 대기’는 당시 상태입니다. 최신 검수 결과는 이 항목을 기준으로 합니다.

```text
Home → Create → Generating → Preview → AI Edit → CMS Editor → Finalize → Download ZIP
```

- Create에서 조건을 선택하고 추가 요청을 입력합니다. 기본값만으로도 생성할 수 있어야 합니다.
- Preview에서 결과를 확인합니다. AI 수정과 CMS 편집은 선택이며 바로 확정할 수도 있습니다.
- AI Edit는 자연어 요청을 검증된 Patch로 반영하고 변경 요약과 Undo를 제공합니다.
- CMS Editor는 Component Tree / Canvas / Property Panel 구조로 직접 편집합니다.
- Finalize에서 구조·데이터·이미지를 검증한 후 다운로드를 허용합니다.
- 확정 이후 다시 편집하면 재확정이 필요하며, 실패 시 마지막 정상 작업을 보존합니다.

생성·Preview·편집·Undo·확정·Export는 동일한 **Dashboard Schema**를 기준으로 합니다.
AI의 임의 HTML/JS를 실행하지 않고, 검증된 컴포넌트와 12열 Grid로 렌더링합니다.
AI 실패나 잘못된 CMS 입력은 기존 정상 Schema를 덮어쓰지 않습니다.

다운로드한 ZIP은 압축 해제 후 `index.html`을 PC 브라우저에서 직접 열어 실행해야 하며,
React 런타임이나 npm 빌드가 필요하지 않아야 합니다. 외부 CDN을 사용하면 인터넷이
필요할 수 있으므로 V1에서 오프라인 실행을 보장하지 않습니다.

작업은 현재 브라우저에 저장됩니다. 브라우저 데이터를 지우거나 다른 기기·브라우저로
이동하면 기존 작업을 복구할 수 없습니다. 최근 작업 보관 수, 이미지 보존 방식,
AI 제공업체·모델·호출 한도 등 미확정 운영값은 구현 단계에서 결정합니다.

## 기술 방향과 개발 순서

프론트엔드는 React + TypeScript + Vite, 백엔드는 Node.js + TypeScript를 기준으로 합니다.
Schema 및 Validation을 공유하고 AI Provider Adapter로 제공업체 의존성을 분리합니다.
React Router, 경량 Store, Zod, Chart.js, 클라이언트 ZIP 라이브러리 등은 기획상의
권장·선정 방향이며 현재 설치 완료 목록을 뜻하지 않습니다.

1. 공통 UI·Routing·Store 및 Schema/Validation 기반 구성.
2. Component Library와 Renderer로 샘플 Schema 렌더링.
3. 스타일·Density, CMS 편집, Undo·자동 저장·최근 작업 복원.
4. Backend AI 생성·Repair 및 AI Edit/Patch 연결.
5. Preview·Finalize·Export 완성, Home/Create 마감.
6. 운영·보안 및 QA → Alpha → Beta → Public V1.

첫 수직 구현 목표는 **Sample Schema → Renderer → CMS 수정 → HTML/CSS/JS 다운로드**입니다.
최소 Export를 먼저 검증하고 AI를 연결합니다. 전체 필수 기능과 대표 E2E 흐름이
통과해야 V1 완료로 간주합니다. PC 1280/1366/1440/1920px의 Chrome·Edge에서
주요 화면, 실패 복구, 접근성 및 Preview와 다운로드 결과의 일치를 확인합니다.

- 편집한 프로젝트명과 수정 시각이 홈의 최근 작업에도 반영됩니다.
- 검증: 프론트엔드 테스트 20개, 백엔드 테스트 5개, Chromium E2E 5개.
  실제 ZIP 다운로드·압축 해제 후 `file://` 실행을 포함합니다.
- 실제 AI 제공업체 호출은 서버 키·모델 설정 후 확인해야 합니다.
  실행 방법과 현재 범위는 [상세 문서](docs/GENERATION_CMS_FINALIZE.md)에 정리했습니다.

## 저장소 구조와 실행

현재 실제 Vite 앱은 루트의 `frontend/`가 아니라 **`sebitcanvers_v3/frontend/`**에 있습니다.

```text
./
├─ README.md
├─ AI_DASHBOARD_BUILDER_V1_PLAN.md
├─ frontend/                         # 예정된 최상위 프론트엔드 위치
├─ backend/
├─ docs/
│  ├─ HOME_IMPLEMENTATION.md
│  ├─ CREATE_IMPLEMENTATION.md
│  ├─ GENERATION_CMS_FINALIZE.md
│  └─ design/
│     ├─ DESIGN_GUIDE.md
│     └─ design_b.png
└─ sebitcanvers_v3/
   └─ frontend/                      # 현재 실행하는 Vite 앱
```

프로젝트 루트에서 실행합니다. PowerShell 스크립트 실행 정책의 영향을 피하도록
Windows 명령은 `npm.cmd`로 표기합니다.

```powershell
cd sebitcanvers_v3/frontend
npm.cmd install
npm.cmd run dev
```

```powershell
npm.cmd run build
npm.cmd run lint
npm.cmd test
npm.cmd run test:e2e
```
